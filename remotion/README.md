# remotion/: фільм 01-natalia і проби переходів

Окремий проєкт Remotion зі своїм `package.json`. Кореневі `package.json`, `scripts/`, `npm test` і `npm run typecheck` його не торкаються (але `remotion/render-film.ts` і тести пропсів імпортують `scripts/lib/film-props.ts`, тож `npm test` у корені перевіряє й збирання пропсів).
Тут композиція повного фільму `Film` (нижче) і проби переходів `TransitionProbe`, за якими режисер вибрав `wc-blots`. Нічого платного і жодних викликів ElevenLabs.

## Фільм: композиція `Film`

1080×1920, 30 к/с, довжина з `edit.md` (зараз 4020 кадрів, 134.0 с). Пропси будує `scripts/lib/film-props.ts` з `stories/<id>/edit.md` і `timings.json` (опис правил у `scripts/README.md`, «Повний фільм»), руками їх не пишуть. Усе, що йде в композицію, JSON (`src/film-types.ts`), час задається номером кадру.

```bash
cd remotion
npx tsx render-film.ts --still 0,226,3950   # стоп-кадри → work/01-natalia/film-stills/still-NNNN.png (~2 с кожен)
npx tsx render-film.ts --test               # кадри 0–711 (титр, переходи 1→2…4→5) → work/01-natalia/film-test.mp4
nohup npx tsx render-film.ts --full > .cache/film-full.log 2>&1 &   # весь фільм → work/01-natalia/film.mp4
npx tsx render-film.ts --range 1500-1700    # довільний шматок → film-range-A-B.mp4
npx tsx render-film.ts --props-only         # лише work/01-natalia/film-props.json
```

Додатково `--crf N` (18 за замовчуванням), `--concurrency N`, `--story <id>`. npm-скрипти `film:props`, `film:test`, `film:full`. Скрипт копіює поточні `work/<id>/frames/frame-NN.png` (без `.v1`, `.v2`) і `mix.mp3` у `.cache/film-public/`, бо `staticFile()` на рендері бере файли звідти. Без `mix.mp3` стоп-кадри рендеряться, а відео ні. Браузер `/opt/pw-browsers/chromium`, `gl: "swangle"`. Студія: `npx remotion studio src/index.ts --props=../work/01-natalia/film-props.json`.

Скільки рендериться: тестовий шматок 0–711 (712 кадрів) 639 с (10 хв 40 с), ~0.9 с на кадр на 4 ядрах, ~23 МБ при crf 18. Це дає ~60 хв на весь фільм (4020 кадрів, переходи складають 45% кадрів у шматку і в фільмі однаково), файл ~125 МБ при crf 18. Титр із розмиттям і переходи найповільніші (software GL), звичайні кадри швидші.

### Як влаштовано

| Шлях | Що це |
|---|---|
| `src/film/Film.tsx` | Композиція: шари кадрів, тон під титрами, вуаль, пляма світла, зернистість, текст титрів, субтитри, звук (`Html5Audio`). Якщо звук коротший за фільм, решта тиша. |
| `src/film/math.ts` | Камера (`cameraAt`, `cameraTransform`), крива проступання, тон під титрами. Усе з номера кадру. |
| `src/film/Title.tsx` | Титр (початковий і фінальний однаковим компонентом): назва, риска, рядки, пляма світла, підгонка назви до блоку по `canvas.measureText`. |
| `src/film/Subtitles.tsx` | Картки субтитрів: заливка, обведення `-webkit-text-stroke` з `paint-order: stroke fill`, тінь. |
| `src/film/fonts.ts` | Lora з Google Fonts: рендер чекає (`delayRender`) таблицю стилів, `document.fonts.load` для кожного накреслення і `document.fonts.ready`. |
| `src/film-types.ts` | Типи пропсів. |
| `src/watercolor/presentation.tsx` | `MaskedReveal`: маска проступання (спільна для проб і фільму). |
| `render-film.ts` | Рендер: стоп-кадри, тестовий шматок, повний фільм. |

Кадри не в `TransitionSeries`, а шарами: кожен наступний кадр проступає своєю маскою `wc-blots` поверх уже видимих, нижче за найвищий повністю проявлений нічого не малюється. Так переходи можуть бути які завгодно за довжиною й накладатися (одночасно видно три кадри) без обмеження «перехід коротший за кадр». Зерно маски в кожного переходу своє (`n4` для першого, `n4-N` для решти), для переходів від 2.5 с вмикається `breath` 0.012. Камера лінійна за кадрами між початком і кінцем вікна кадру (усе вікно, разом із переходами). Зернистість паперу (5.5%) і потемніння по краях (8%) лежать на всьому фільмі, не тільки під титрами (це тлумачення, див. звіт). Фільтри розмиття, насиченості й додатковий масштаб кадру під титрами накладаються на стос кадрів цілком.

## Версії

Remotion 4.0.541 (`remotion`, `@remotion/cli`, `@remotion/bundler`, `@remotion/renderer`, `@remotion/transitions`), React 19, TypeScript. Node 22.
`@remotion/noise` не використано: він тримає в кеші лише 10 генераторів шуму і на наших масках перестворював би їх на кожен піксель, тому браузер зависав. Власна обгортка над тим самим `simplex-noise` лежить у `src/watercolor/noise.ts`.

## Як ставити

```bash
cd remotion
npm install
```

Браузер. Remotion сам намагається завантажити свій Chrome. Якщо це не вдається, `render.ts` і `remotion.config.ts` беруть `/opt/pw-browsers/chromium` (Chrome for Testing 153). Інший шлях можна задати змінною `REMOTION_BROWSER_EXECUTABLE`.

Шейдерні переходи на SwiftShader повільні: `linearBlur` рендериться ~24 хв, решта по 1-1,5 хв. Переходи на шейдерах (`linearBlur`, `crosswarp`, `zoomInOut`, `dreamyZoom` та інші HTML-in-canvas) потребують WebGL2. У контейнері без GPU він працює тільки з програмним рендерером SwiftShader, тому `render.ts` запускає Chromium з `gl: "swangle"` (змінна `REMOTION_GL` це перекриває). З `angle` або `angle-egl` шейдерні переходи падають з `Failed to create WebGL2 context`.

## Як рендерити

Кадри читаються з `work/01-natalia/frames/frame-01.png` ... `frame-04.png` (у git не йдуть). Скрипт копіює їх у `remotion/.cache/public/frames/`, і композиція бере їх через `staticFile()`.

Спершу тестовий рендер, бо шляхи й шрифти ламаються тільки на рендері:

```bash
# один кадр середини першого переходу (кадри 75..110 це перехід 1)
npx tsx render.ts --only wc-bloom-edge --still 93
# короткий шматок відео
npx tsx render.ts --only wc-bloom-edge --range 70-115
```

Тестові файли лягають у `work/01-natalia/transitions/` (`still-*.png`, `test-*.mp4`), їх можна видаляти.

Повний рендер усіх варіантів (довгий, запускай у фоні):

```bash
nohup npx tsx render.ts --crf 27 > .cache/render.log 2>&1 &
tail -f .cache/render.log
```

Після рендеру стискай до бюджету (14 МБ на всі файли). Рендер дає по ~1,8 МБ на файл, `compress.ts` перекодовує їх ffmpeg у два проходи приблизно до 640 кбіт/с:

```bash
npx tsx compress.ts            # --budget-mb 13.5 за замовчуванням
npx tsx render.ts --index-only # оновити index.json із новими розмірами
```

Параметри: `--only id,id` (лише ці варіанти), `--crf N` (якість, більше означає менший файл), `--out dir` (куди класти, за замовчуванням `work/01-natalia/transitions/`).
Після повного рендеру пишеться `work/01-natalia/transitions/index.json`: для кожного файлу назва українською, опис, тривалість, розмір.

Студія для перегляду в браузері: `npm run studio` (шейдерні переходи там потребують Chrome 149+ з увімкненим Canvas Draw Element).
Перевірка типів: `npm run typecheck`.

## Часова схема проби

Кожен кадр має 75 кадрів (2,5 с) чистого показу, між кадрами перехід 36 кадрів (1,2 с). Разом 408 кадрів, 13,6 с. Наїзд іде весь час життя кадру, разом із ділянками переходу. Масштаб і прогрес переходу рахуються з номера кадру (`useCurrentFrame` і таймінг `linearTiming` з кривою Безьє), без стану React.

## Як влаштовані акварельні переходи

Новий кадр показується через маску, що росте. Маску рахує код (шум simplex), зовнішніх масок немає.

1. `field.ts` будує для характеру ("розтікання", "пляма з краю", "кілька плям", "змив", "намокання") поле "часу відкриття" кожного пікселя: відстань до плям, викривлення простору і кілька шарів шуму. Потім значення вирівнюються за рангом, тож відкрита площа росте рівно за часом.
2. `mask.ts` для кожного кадру переходу порівнює час із полем і робить PNG-маску (чіткість краю задає `soft`) та додатково слабкий шум, що "дихає" (`drift`), щоб край жив.
3. Облямівка пігменту (`edge`): друга копія нового кадру множиться сама на себе по вузькій смузі біля краю, тож край темнішає власним кольором кадру. Нерівність смуги задає шум-зерно. За бажання додається ще й підфарбування (`tint`).
4. `presentation.tsx` накладає маску CSS `mask-image` на новий кадр. Рендер чекає (`delayRender`), поки маска декодується, щоб кадр не знявся без неї.

## Повільні версії

Для трьох відібраних режисером акварелей (`wc-blots`, `wc-wet`, `wc-wet-edge`) є версії в 5 і 10 разів повільніше (перехід 6 с і 12 с): `wc-blots-x5.mp4`, `wc-blots-x10.mp4` тощо. Вони описані в `src/variants.ts` (`SLOW_VARIANTS`). Ті самі кадри й наїзд, кадр тримається 2,5 с, але показано три кадри і дві склейки (1→2 і 2→3), щоб шість роликів вкластися в бюджет без падіння якості. Рендер:

```bash
npx tsx render.ts --crf 24 --only wc-blots-x5,wc-blots-x10,wc-wet-x5,wc-wet-x10,wc-wet-edge-x5,wc-wet-edge-x10
npx tsx compress.ts --budget-mb 11.5 --only wc-blots-x5,wc-blots-x10,wc-wet-x5,wc-wet-x10,wc-wet-edge-x5,wc-wet-edge-x10
npx tsx render.ts --index-only
```

Зерно й форма країв прив'язані до прогресу переходу, тож при сповільненні плями просто ростуть повільніше. Щоб довгий перехід не мертвів, додано параметр `breath`: дрібний шум краю, що рухається в реальному часі (секундах), а не за прогресом. Його амплітуда мала (0,012-0,014 проти м'якості краю 0,07-0,4), тому піксель не стрибає туди-сюди, а край лише ледь мерехтить і живе.

## Що пробували і відкинули

- `dissolve()`: випалює за яскравістю старого кадру, на малюнку виходить постеризований цифровий край, який не схожий на акварель. Прибрано з проб.
- `ripple()`: рендериться, але на мальованому кадрі це схоже на подвійну експозицію з брижами, і він майже повторює `crosswarp`. Прибрано, щоб не роздувати вибір.
- Яскраві й техно-переходи (кубики, шторки, flip, film burn, cross-zoom) не пробувались за завданням.
